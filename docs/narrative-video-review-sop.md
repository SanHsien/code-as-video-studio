# 敘事影片分鏡與人工審片 SOP

適用於有角色、對話或跨鏡動作的敘事影片；純產品 UI／字卡鏡頭可逐項 N/A，附理由與人工核准者。這是製作決策紀錄，沒有新增 ASR 引擎、關鍵字驗證器或模型品質硬閘門。搭配[鏡頭卡](../templates/cinematic-storyboard-template.md)與[合成範例／檢查證據](evidence/narrative-review-examples.md)。

## 七條建議的採納決策

以下編號沿用來源筆記七條建議；屬本 repo 的流程選擇，並非官方背書或經實測的品質提升。每張卡填實際承辦人；表中角色可兼任。

| #／原建議 | 決策與理由 | 適用條件／N/A 理由示例 | 鏡頭卡欄位／人工決策者 |
| --- | --- | --- | --- |
| 1 台詞預審與讀音展開 | 採用：先核准正本與難讀詞；僅對需要的詞註讀音，避免整篇改寫失去語意 | 有台詞先審人名、多音字、專業詞及語言；無台詞 N/A | 台詞／讀音：詞、預期讀法、正本版本；語言審查者核准，導演確認表演意圖 |
| 2 Whisper 逐字驗收、錯一詞即 Retake | 條件採用 ASR 篩檢；不採用「ASR 一詞不符就自動重拍」：轉錄會出錯，正字也不能證明讀音 | 有音訊可沿用既有工具；無台詞 N/A，無音訊或工具失敗為待審，不是 N/A／合格 | ASR 線索＋人工聽審＋修正；語言審查者逐一聽關鍵詞，導演決定重錄／局部修補／保留 |
| 3 全身三視角色表 | 條件採用：可見身體與跨鏡角色需要一致基準，不強迫所有特寫製作不可見細節 | 全身／轉身／下衣入鏡時備正側背、鞋襪、配件；純物件 N/A，臉部特寫可註明下衣不入鏡 | 角色參考＋服裝／站位；素材負責人確認可用權利，連戲審查者確認覆蓋可見範圍 |
| 4 Last-frame → start_image 連續鎖定 | 條件採用參照；不採用「鎖定」保證：末幀不保證人物或衣服一致 | 僅所選模型／版本支援且鏡頭連續才採用；換機位、反打、跳時可 N/A；能力未知先停送出。每段提示詞都重寫位置關係（場所、相對距離、左右）與已放下的道具，不假設模型記得上一段 | 前鏡接點＋start_image 決策＋接點人工比對；導演選擇，操作者附官方能力 URL／日期／實際參數，連戲審查者比對 |
| 5 禁連續並排固定鏡、每段強制反應與 Insert | 條件採用分鏡選項；不採用每段配額：景別由敘事目的決定 | 需要聽者情緒時加反應；動作資訊不清時拆 Insert；刻意長鏡或保留同框關係可 N/A | ②／⑤＋反應／Insert；導演記錄看誰、為何切或不切，連戲審查者核站位、視線與動作合理性 |
| 6 一律動作中 Hard Cut | 條件採用：動作接點可直切；不採用統一轉場命令 | 連續動作可 cut；時間流逝可 dissolve；風格性定格／閃白需目的與人工審片，無動作接點 N/A | 轉場＋轉場理由＋接點比對；導演／剪輯者決定，不因選 hard cut 就自動合格 |
| 7 口述錄影交模型、效率遠高於文字 | 不採用預設錄影／外送與效率保證；採用去識別文字＋時間碼修正單 | 文字足以定位時不錄；確需錄影另依隱私流程與明確授權，無素材 N/A | 修正／回饋；審片者列症狀與預期，素材負責人審隱私，導演核准修正優先級；效率僅待驗證假設 |

`start_image` 在本文件是工作流概念名稱，不能推定各服務都有同名 API 參數；使用前必須查所選模型官方文件。這次沒有選定或驗證生成模型（來源案例用的 Seedance 2.5 是中國廠商的模型，本 repo 不採用，見文末來源段），合成範例中的「可用」只表示條件成立時的設計選項。

## 執行與停止條件

```text
角色基準 + 正本/難讀詞 -> 人工預審 -> 鏡頭卡 + N/A 理由
                                         |
                                  分鏡計畫檢查
                                         |
                            素材存在後才做成品 QA
                                         |
                  ASR 疑點 + 接點比對 + 關鍵詞人工聽審
                                         |
                      修正單 -> 受影響片段複核 -> 人工放行
```

1. 導演確認敘事目的；連戲審查者在卡上記服裝版本、下衣／鞋襪、持物手、畫面左右、視線、光向與動作階段。每一鏡的提示詞都要重寫角色位置關係與場上已放下的道具（例如插在地上的武器），不能只寫在第一鏡。沒有必要參考、模型能力未確認或正本未核准，先停止該鏡送出。
2. 現有分鏡 JSON 仍走 `verify_video_storyboard.py`，動畫 HTML 成品仍走 `audit_motion_storyboard.py`，兩者不能互代。Markdown 鏡頭卡不能直接當 JSON 輸入；計畫分數不是視聽品質證明。[工具分工](../README.md#兩支分鏡工具的分工)
3. 有素材後並排看連續接點兩幀，並播放接點前後檢查動作；切換機位以各鏡獨立構圖、角色基準與視線關係審查，不硬塞上一鏡末幀。記實際差異及審查人，不能只寫「一致」。
4. 沿用 ASR 的時間窗與轉錄文字定位疑點；語言審查者對照正本與核准讀音，實際聽每個關鍵詞，必要時先聽乾淨人聲再聽成片。ASR 相同仍需聽，ASR 不同也可能是轉錄錯誤。無音訊／缺依賴／執行錯誤／逾時皆記未完成，不自動通過或重拍。
5. 聽審記錄至少含素材版本、Shot ID、全片時間碼、詞、預期讀音、ASR 線索、實際聽到的讀音、審查人及結論。導演依確認問題決定重錄、局部修補或附理由保留；修後只複核受影響台詞、字幕同步與接點。無關項目達標即停；未完成必要項目不得簽成片通過。

## 回饋與錄影隱私

預設修正單只留去識別文字、Shot ID、相對片頭時間碼與預期改動。不提交影音、私人逐字稿、帳號、機密或真實家目錄；參考素材只記去識別 ID、版本與允許公開的來源。

確需錄影時，素材負責人先核准用途、範圍與保留位置；關閉無關視窗、通知、帳號頁、私有專案與金額頁，限錄內容區。錄後先本機逐段看全畫面，依現行流程做 OCR 輔助檢查並人工核讀；OCR 缺失或漏辨不能視為安全。遵循上述 SECURITY 的人工全幀檢查原則，不自動上傳；任何外送另需明確授權及目的地資料政策核對，私有素材預設不外送。

若產生錄影、抽幀、音訊或 OCR 暫存，指定素材負責人於建立後 48 小時內清理並記去識別清理結果；這是本任務沿用的保留規則，不是工具會自動清除的承諾。無法清理或發現敏感內容時停止分享並交素材負責人處理。本次只寫文件，沒有建立此類媒體。

## 來源與查證邊界

- [OpenAI Whisper 官方 model card](https://github.com/openai/whisper/blob/main/model-card.md#performance-and-limitations)，2026-11-15 讀取：轉錄可能含音訊未說出的文字、語言及口音表現有差異。因此 ASR 僅作線索；本流程的人工聽審是本 repo 決策，沒有宣稱 ASR 有讀音判定能力。
- [Higgsfield 官方連接指南](https://higgsfield.ai/creator-hub/help-center/integrations/how-do-i-connect-higgsfield-to-ai-agent)，2026-11-15 讀取：要求有效付費訂閱，客戶端連接方式有別。此頁只支持連接前提，不支持影片覆盤、末幀一致性或效率宣稱；本任務不連接、不安裝、不付費、不呼叫服務。
- [Okihiro 個人覆盤報告](https://okihiro-school.com/opus55-review-report/)與[作者說明文章](https://okihiro-school.com/opus-5-5-higgsfield-ai-video-app/)（2026-10-06，標示含廣告／推廣）。2026-11-15 網頁工具取不到報告，當時寫「均未獨立查證」；2026-11-17 已用瀏覽器讀到報告全文與說明文章，細節與頁面一致：第一版 79 秒、作者邊看邊講的添削影片 6 分 15 秒、報告日期 2026-09-26、九項指摘（含台詞誤讀、正側面並排構圖、接點處站位與服裝不一致）、出拳前停格 0.3 秒接白閃再進標題。查證的是「報告這樣寫」；影片沒有逐支看，報告本身是 Claude（Opus 5.5）依作者口述整理的，台詞對照用 Whisper 轉寫，報告自己註明轉寫可能聽錯。仍是單一作者的個人案例，不寫成官方共同背書。
